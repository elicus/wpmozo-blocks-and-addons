Each entry: ID, date approved, decision, reason. Proposed or open items are not listed here; they live in [handoff.md](handoff.md) (open questions) and [roadmap.md](roadmap.md) (proposed stages from the 2026-11-05 audit). An approved change to a decision is added as a new entry that names the entry it replaces; old entries are never rewritten. The full reasoning and alternatives are in [architecture-readiness-review.md](architecture-readiness-review.md) (section in brackets). | PL-D12 | 2026-11-03 | **Restricted-HTML detection (implements PL-D05):** per pattern, compare a structural fingerprint (blocks and comment attributes, every tag with its attribute names and decoded values) of the content before and after `wp_kses( $content, 'post' )`. No hand-maintained block list | Measured on 108 WPMozo blocks (WordPress 6.8.11 and 7.1.3): 44 change under the Author save filter, 43 then fail validation. A "blocks that save `<style>`" list would miss Ajax Search, Bar Chart and Pie Chart. A byte comparison would wrongly lock core images (`/>` vs ` />`). The fingerprint matches the measured list exactly ([security.md](security.md)) |
| PL-D13 | 2026-11-03 | **Validator rules** as listed in [security.md](security.md):<ul><li>HTML checked tag by tag with WordPress's HTML Tag Processor (decoded attribute values);</li><li>exceptions only for the exact no-op `javascript:void(0)` that WPMozo buttons save and for microdata `<meta itemprop>`;</li><li>text attributes starting with `Data:` are rejected (documented strictness).</li></ul> | Regex over raw text missed entity- and tab-encoded `javascript:`, and rejected harmless text. All 67 Lite blocks' default markup passes; 13 attack probes are rejected |
| PL-D14 | 2026-11-03 | **Analysis cache** (key extended by PL-D23):<ul><li>one transient per source (one-week expiry);</li><li>key = source id, source version, central-map modification times;</li><li>entries reused only while revision and `content.php` modification time are unchanged;</li><li>no other stored data.</li></ul> | Catalog requests stay fast without trusting authored "blocks used" lists. **Process (approved 2026-11-03):**
- Lite Pattern Library work goes on `dev/sunil`; Pro Pattern Library work on `release/pattern-lib`.
- Approved work is committed and pushed automatically in small verified units, code and docs in separate commits. No force-push, reset or merge of other branches.
- These rules apply to the current developer. Ayush's branch and pull-request workflow, and its reviewer, are an open decision for the owner ([handoff.md](handoff.md), "Release readiness"; noted 2026-11-23).
