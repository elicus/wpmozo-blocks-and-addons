# Pattern Library decisions (approved only)

Each entry: ID, date approved, decision, reason. Proposed or open items are not listed here; they live in [handoff.md](handoff.md). The full reasoning and alternatives are in [architecture-readiness-review.md](architecture-readiness-review.md) (section in brackets). Licence and Pro-security details are recorded in the private Pro repository.

| ID | Approved | Decision | Reason |
|---|---|---|---|
| PL-D01 | 2026-10-31 | Lite owns the pattern registry, the asset-resolution contract and the future CDN setting. Pro registers through Lite. | One owner for shared infrastructure; Pro never builds URLs or UI ([CDN requirement](cdn-and-asset-requirements.md)) |
| PL-D02 | 2026-10-31 | Local-first: no CDN, remote catalog, remote media or external service. Lite JS, CSS and Lite assets always ship in the plugin (U1). | WordPress.org guidelines 7 and 8; works offline ([CDN requirement §7–8](cdn-and-asset-requirements.md)) |
| PL-D03 | 2026-11-03 | Images placed into page content are local, project-owned files and never depend on a CDN (D7/U7). Media Library import is a later, separate option. | Saved content must survive any CDN outage or switch ([review §0, C/D7](architecture-readiness-review.md)) |
| PL-D04 | 2026-11-03 | **Architecture contract (A1):** Lite owns catalog, REST routes, validator, importer, UI, design tokens, central maps and the asset resolver. Add-ons supply data and one server-side entitlement callback. One folder per pattern, PHP files only. Blocks are rebuilt on insert with fresh IDs; nothing is inserted if validation fails. Post editor only; entry points through public editor APIs (no DOM injection). Library patterns are not added to core's pattern registry in v1. | Single validated import path; premium content can't be exposed through core's pattern endpoint; no duplicated UI ([review §0.4, A1–A7](architecture-readiness-review.md)) |
| PL-D05 | 2026-11-03 | **Restricted HTML (A2):** patterns that use blocks saving `<style>` or raw HTML are unavailable to users without `unfiltered_html`, with the reason shown, and the server refuses their content. The affected-block list is measured at the start of Stage C. | Inserting them for those users produces broken content on save ([review C/D3](architecture-readiness-review.md)) |
| PL-D06 | 2026-11-03 | **Premium access (A3):** premium content is authorised on the server for every request. The catalog never contains content or licence data. Licence state is described only as what the site can know ("activated"). Content already inserted into pages is never changed by licence or plugin state. | Hiding cards is not protection; no claims the system can't verify (details in the private Pro repository) |
| PL-D07 | 2026-11-03 | **Initial catalog (A4):** a pilot of 2 free + 2 Pro patterns, reviewed by the owner, then up to 10 free + 14 Pro across 8 categories behind a quality gate. No filler. | Quality over count; each pattern has a real authoring and test cost ([review §0.6](architecture-readiness-review.md)) |
| PL-D08 | 2026-11-03 | **Roadmap (A5):** experiments run at the start of the stage that needs them; docs are written by the stage that implements them; two review checkpoints: UI prototype (LPL-UX) and pilot patterns (LPL-T). | Fewer planning gates without losing evidence or product review ([review G](architecture-readiness-review.md)) |
| PL-D09 | 2026-11-03 | **Tooling (A7):** only installed tools, plus PHPCompatibilityWP installed inside the test harness (not globally) for PHP 7.3 checks. | Static check for the PHP version the header claims ([review §0.7](architecture-readiness-review.md)) |
| PL-D10 | 2026-11-03 | **Defaults approved with the baseline (review §0.3):** <ul><li>metadata and UI translatable, demo content in English;</li><li>library on/off switch (default on) and `edit_posts` capability, filterable;</li><li>static previews;</li><li>one dismissible Lite-to-Pro card after the free patterns, destination configurable;</li><li>`@wordpress/components` + `@wordpress/base-styles` + project tokens;</li><li>performance budgets;</li><li>per-source CDN switch (future).</li></ul> | Reversible technical choices, documented so they aren't re-decided |

Block build output verified byte-identical ([registry-and-contract.md](registry-and-contract.md)) |

## Implementation decisions (within the approved architecture)

| ID | Date | Decision | Reason |
|---|---|---|---|
| PL-D12 | 2026-11-03 | **Restricted-HTML detection (implements PL-D05):** per pattern, compare a structural fingerprint (blocks and comment attributes, every tag with its attribute names and decoded values) of the content before and after `wp_kses( $content, 'post' )`. No hand-maintained block list | Measured on 108 WPMozo blocks (WordPress 6.8.11 and 7.1.3): 44 change under the Author save filter, 43 then fail validation. A "blocks that save `<style>`" list would miss Ajax Search, Bar Chart and Pie Chart. A byte comparison would wrongly lock core images (`/>` vs ` />`). The fingerprint matches the measured list exactly ([security.md](security.md)) |
| PL-D13 | 2026-11-03 | **Validator rules** as listed in [security.md](security.md):<ul><li>HTML checked tag by tag with WordPress's HTML Tag Processor (decoded attribute values);</li><li>exceptions only for the exact no-op `javascript:void(0)` that WPMozo buttons save and for microdata `<meta itemprop>`;</li><li>text attributes starting with `Data:` are rejected (documented strictness).</li></ul> | Regex over raw text missed entity- and tab-encoded `javascript:`, and rejected harmless text. All 67 Lite blocks' default markup passes; 13 attack probes are rejected |
| PL-D14 | 2026-11-03 | **Analysis cache:**<ul><li>one transient per source (one-week expiry);</li><li>key = source id, source version, central-map modification times;</li><li>entries reused only while revision and `content.php` modification time are unchanged;</li><li>no other stored data.</li></ul> | Catalog requests stay fast without trusting authored "blocks used" lists. Updates and edits invalidate automatically |
| PL-D15 | 2026-11-03 | **Placeholder block** `wpmozo/pattern-library`:<ul><li>always registered;</li><li>saves an empty comment and renders nothing;</li><li>hidden from the inserter in `block.json`; the library script shows it with a `blocks.registerBlockType` filter plus `reapplyBlockTypeFilters()`;</li><li>no automatic opening on insert;</li><li>rejected inside pattern content.</li></ul> | Saved placeholders must never break, even with the library off or in other editors. The library script already loads only where the library can be used, so the inserter rule needs no second copy of those conditions. Opening on insert can't tell a new block from a saved one |
| PL-D16 | 2026-11-03 | **Library switch saving:** `panel-library.js` adds the switch to the settings panel's existing save request with `jQuery.ajaxPrefilter`. The panel script and the save handler are unchanged | `panel.min.js` has no source in the repository, so editing it is unsafe. The save handler already stores any submitted option key. One request, one Save button |

| PL-D18 | 2026-11-04 | **Patterns are authored on the minimum supported WordPress (6.8).** The importer accepts raw attributes that a block's deprecations declare. | Newer WordPress migrates older block markup through deprecations, but older WordPress can't read newer markup. Without the importer rule, 7.1 refused valid 6.8 content |
| PL-D19 | 2026-11-04 | **Export removes attributes derived from the editor ID** (`ID`, `wrapStyle`) and fails if any client ID remains. | They are site- and insert-specific. The importer and the blocks recreate them. `wrapStyle` also holds braces, which the validator rejects |
| PL-D20 | 2026-11-04 | **Pilot content:**<ul><li>2 free (hero, pricing) + 2 Pro (features, process), temporary designs;</li><li>WPMozo blocks are the featured elements;</li><li>CTAs use core Buttons;</li><li>blocks with front-end defects are avoided;</li><li>fonts follow the theme, colours come from one token set;</li><li>original local illustrations.</li></ul> | Owner asked for production-quality temporary designs without supplying them (2026-11-04). The block issues are listed in [testing.md](testing.md) |
| PL-D21 | 2026-11-04 | **Temporary Lite-to-Pro card link** on the reserved `example.com` domain, marked in `data/links.php`. | Owner: use a clearly marked temporary value until the destination is confirmed; never invent a production URL. Replacing it is a release blocker |

**Process (approved 2026-11-03):**
- Lite Pattern Library work goes on `dev/sunil`; Pro Pattern Library work on `release/pattern-lib`.
- Approved work is committed and pushed automatically in small verified units, code and docs in separate commits. No force-push, reset or merge of other branches.
