# Known issues and risks

Confirmed issues were reproduced; each names the run that shows it. Potential risks were found by reading code or platform changes and were not reproduced as failures. Fixes are proposals until the owner approves the roadmap ([roadmap.md](roadmap.md)); nothing here has been fixed yet unless its status says so.

Issues specific to Pro (licence flow, Pro blocks, Pro requirements) are tracked in the private Pro repository; this public file names them only where they affect compatibility with Lite.

**Updated:** 2026-11-06 (R4). Harness runs: `sessions/audit/` ([testing.md](testing.md), "Compatibility audit").

## Confirmed: blocks (found by library work; separate tasks)
Found during the pilot (2026-11-04, [testing.md](testing.md)); not part of the library and not fixed:
- Advanced Button saves `href="javascript:void(0)"` and never outputs its URL.
- Thirteen Lite block scripts use jQuery without declaring it (listed in testing.md, LPL-T).
- Pricing Table: no way to remove the theme's link underline on its button; `price` declared as a string with a numeric default; price and period share one colour; the divider is always black.
- Star Rating rounds to half stars.
- Lite blocks reset their `ID` to the editor's client ID on every load, so a post always shows as changed after opening (seen again in every 2026-11-05 browser run).

**Found during R4 (2026-11-06).** Pattern Library work never changes block code (PL-D29): these are recorded for a separate developer, to be handled after the Pattern Library is complete. ## Confirmed: Pro compatibility with Lite (detail in the Pro repository)
- Pro from the Pattern Library branch needs a Lite with the integration contract. With Lite 1.8.0, Pro blocks crash in the editor; the only warning is a Plugins-screen notice (run c07). **Corrected in R5 (2026-11-05):** that crash came from a 1.8.0 copy without its generated block manifest, which registered no Lite block. With the manifest the Pro block mounts; the editor notice is still missing, and Pro's editors still depend on globals that a Lite without the contract sets only through its block scripts ([testing.md](testing.md), R5 results). A support floor and an editor notice are proposed ([roadmap.md](roadmap.md), stage R2). **R2 investigation (2026-11-05, shipped 1.8.0):** with every Lite block switched off, Lite sets none of those globals, and Pro blocks crashed, showed "invalid content", and made the editor lose later edits. **Fixed in R2:** Pro checks the globals in the editor and switches its block editing off only when they are missing (details in the Pro repository; [testing.md](testing.md), R2).
- Pro's Team Grid templates use PHP 8.0 syntax, so they fail to parse on PHP 7.4 (static runtime parse, 2026-11-05). **Fixed in R3:** every PHP file of both plugins now parses on PHP 7.4, and Team Grid renders on PHP 7.4 with unchanged markup ([testing.md](testing.md), R3).
